Privacy Policy

What CheckDR processes, what it does not store, and which analytics providers operate on the site.

What the tools receive

The site does not require an account, login, API key, or credentials for Ahrefs, Google, hosting, FTP, analytics, or any other account. Depending on the tool, visitors can submit domains, URLs, or keywords for processing.

The CheckDR application code does not write submitted domains, URLs, or keywords to an application database. This statement describes the application code; it is not a claim that hosting, proxy, or service providers do not process request data.

Rate-limit information

For tools that use the backend, the Worker reads the visitor IP from the Cloudflare-provided CF-Connecting-IP header (falling back to X-Forwarded-For) for hourly rate limiting. The KV counter key contains the IP, tool name, and hourly window; it does not contain the submitted domain, URL, or keyword. The Worker code sets an expiry of 3,700 seconds on these counters.

Those rate-limit counters automatically expire after roughly one hour. They are not sold, shared, or used for another purpose by CheckDR.

Analytics providers and information collected

CheckDR loads Google Tag Manager and Ahrefs Web Analytics only after a visitor selects Accept analytics. Neither analytics script is requested before acceptance. Selecting Reject prevents either service from loading.

Google Analytics through Google Tag Manager

Google Tag Manager (container GTM-PP972P5P) loads tags. CheckDR does not load a separate, hard-coded Google Analytics script. Google Analytics 4 runs as a tag configured inside this GTM container. When the tag fires, Google Analytics can collect page views, site interactions, page/referrer information, approximate location, and browser/device information. The precise events and any additional tags depend on the live GTM container configuration.

GTM itself is a tag manager, not the analytics service. A GA4 tag commonly uses first-party cookies _ga and _ga_* for browser identification and analytics state. Other tags configured in GTM may set additional cookies.

Ahrefs Web Analytics

After acceptance, CheckDR loads Ahrefs Web Analytics from analytics.ahrefs.com using the existing project key. Ahrefs collects page URLs (including URL parameters), referrers, user-agent information used to report browser/device/operating-system details, country/city-level location, language preferences, and screen size. It automatically measures common interactions such as page views, link clicks, and form submissions. Ahrefs derives a daily pseudonymous visitor ID from IP address and user-agent data; it says raw IP addresses are discarded, the identifier is not used to track visitors across days, and it does not track people across devices or sites.

Ahrefs Web Analytics states that it uses no cookies or persistent identifiers. Therefore it is not expected to set analytics cookies. Google Analytics cookies may be set if/when a GA4 tag in GTM is configured and runs. The consent choice is stored in this browser's local storage under checkdr-analytics-consent, not in an analytics cookie.

Provider details: Google Analytics data collection, Ahrefs Web Analytics data collection, Google's Privacy Policy, and Ahrefs' Privacy Policy.

Cloudflare Web Analytics

Cloudflare Web Analytics is controlled through a setting in the Cloudflare dashboard for the site's zone. When automatic injection is enabled, Cloudflare injects its beacon at the edge; it is not added by this repository's HTML or JavaScript. Whether it is currently enabled must be checked in the Cloudflare dashboard. When enabled, it operates independently of the optional Google Analytics and Ahrefs consent choice and is not controlled by the cookie banner. Cloudflare documents that Web Analytics does not use cookies or local storage to identify visitors, and describes collecting page/performance measurements through the browser Performance API. The exact beacon presence and configuration are controlled in the Cloudflare dashboard, not this repository.

See Cloudflare's Web Analytics setup guide, data origin and collection documentation, and Web Analytics overview.

Cloudflare Turnstile

The Dofollow/Nofollow Link Checker is the CheckDR tool that loads Cloudflare Turnstile. Its page loads the Turnstile JavaScript API; the backend verifies the returned token with Cloudflare's Siteverify service. The Worker forwards the visitor IP in the Siteverify request when the CF-Connecting-IP header is present. Cloudflare's documentation describes Turnstile processing signals such as the visitor IP address, user-agent, and browser/device signals to assess automated traffic. This security processing is separate from the optional analytics consent choice.

See the Cloudflare Turnstile documentation, Turnstile implementation guide, and Cloudflare Turnstile Privacy Addendum.

Changing or withdrawing consent

Select Cookie settings in the footer to review or change your current choice. Opening settings does not change or withdraw consent. Close or press Escape to dismiss the banner while keeping your existing choice. Select Accept analytics to enable Google Analytics through Google Tag Manager and Ahrefs Web Analytics; this grants only the analytics_storage consent signal. Advertising-related consent signals remain denied. Select Reject to deny analytics consent and prevent the optional analytics scripts from loading on subsequent page loads.

If Google Tag Manager or Ahrefs Web Analytics has already loaded in the current page, choosing Reject updates consent, clears known Google Analytics/advertising cookies where possible, and reloads the page because already-running third-party scripts cannot be reliably unloaded in place. Your choice is stored in this browser's local storage. Cloudflare Web Analytics traffic statistics and Cloudflare Turnstile security checks are not controlled by this optional analytics setting. Clearing site data or using another browser/device resets the saved choice.

Third-party sharing

CheckDR does not sell personal information. Providers involved in hosting, proxying, security, and analytics may process visitor or request information as necessary to provide their services. These providers include:

  • GitHub Pages — hosts the site's static HTML, CSS, JavaScript, and other site assets. See GitHub's General Privacy Statement.
  • Cloudflare — provides DNS/proxy services and the Worker backend; it also provides the dashboard-managed Web Analytics beacon and Turnstile token verification described above. See Cloudflare's Privacy Policy, Cloudflare proxy/IP documentation, and the linked Web Analytics and Turnstile documentation.
  • Google — Google Tag Manager and any Google Analytics tags configured in the GTM container are requested only after analytics acceptance. See Google's Privacy Policy.
  • Ahrefs — Ahrefs Web Analytics is requested only after analytics acceptance. See Ahrefs' Privacy Policy.

Hosting, proxy, and security providers necessarily receive network/request information when browsers connect to the site or use protected features. The optional Google and Ahrefs analytics scripts are governed by the saved analytics choice described above. Cloudflare Web Analytics is dashboard-managed and is not controlled by that choice.

Domain Rating data

Domain Rating data comes from Ahrefs' public Domain Rating API. CheckDR retrieves and displays that metric; it does not calculate Domain Rating itself.
