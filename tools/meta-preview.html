Meta preview

Inspect search and social metadata before you publish or audit a page.

Reading page metadata

What does a meta preview do?

A meta preview surfaces the HTML signals that commonly describe a page to search engines and social platforms: title, description, canonical URL, Open Graph fields, Twitter fields, robots directives, and the number of H1 elements.

Why and when to use it

Use it during SEO audits, launches, migrations, and content reviews to spot missing or inconsistent metadata. A preview is especially useful when the page source is difficult to inspect quickly across several URLs.

How it works

The tool makes a read-only HTTP request, validates the target hostname and each redirect, then reads at most 300 KB of the response body. It parses metadata with lightweight patterns and never executes JavaScript from the target page.

Frequently asked questions

What is a meta preview?

A meta preview shows the title, description, canonical URL, social metadata, robots directive, and H1 count detected near the top of a fetched HTML document.

Does this tool change my page?

No. It makes a read-only request and parses the returned HTML. It does not execute scripts or modify the target site.

How many URLs can I check?

Up to 8 URLs can be checked per request, with a 50-subrequest Worker budget shared across the batch.

How to read a meta preview

The results show metadata detected in the HTML returned for a public URL. Review the document title and meta description first, then compare the canonical URL, robots directive, H1 count, and social tags. The title and description describe the page to searchers, while the canonical tag signals the preferred URL when similar or duplicate addresses exist. Open Graph and Twitter metadata provide title, description, and image information that social platforms may use when generating a shared link card.

Use the result as a diagnostic snapshot rather than a guarantee of how a search engine or social network will display the page. Search engines can select a different snippet, and social platforms may cache an earlier version or apply their own image crops. The checker reads returned HTML and does not execute page scripts or change the source site. If a page relies on JavaScript to insert metadata after load, that metadata may not be included in the fetched response.

A common mistake

Do not assume that a missing social image tag means the page has no image, or that a present tag guarantees a correct preview. Check that the referenced image is public, loads without authentication, and has suitable dimensions.

Frequently asked questions

Will Google use this exact description? Not necessarily; snippets can be rewritten.

Does the checker edit my page? No, it only reads the fetched HTML.

Why do social cards look different? Platforms cache and crop previews differently.
